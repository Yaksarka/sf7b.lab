## Goals / Non-Goals

**Goals:** завершать обнаруженные возможности целыми пользовательскими сценариями; сохранять редактируемость и исходные ресурсы; подтверждать качество и скорость на A51. One Lab определяет основную компоновку, Glitch дополняет функции. Все пользовательские возможности выбранных версий входят в инвентаризацию, включая доступные временные режимы.

**Non-Goals:** в этом запросе — запуск реализации, сборок и опытов на телефоне. При последующей разработке — копирование чужих материалов в продукт, платная или сетевая обработка, подмена выбранных версий последними версиями без отдельного основания. Обнаруженные ограничения не удаляются из карты покрытия.

## Decisions

### Параметры работы агента

| Параметр | Правило |
|---|---|
| Модель всех агентов | Только `gpt-6.1-sol`; не подменять другой моделью |
| Размышление | `medium` обычно; `high` для сложного анализа/исправлений; `xhigh` («очень высокий») при необходимости; `low`, `max`, `ultra` исключены |
| Делегирование | Обычно 0–2 субагента: независимые вопросы, один владелец каждого изменяемого файла; повторно использовать существующих агентов |
| Выходные токены | Короткий итог; находки, исходники и полные логи — в файлах; не пересказывать повторно большие документы |
| REA | Оригинальные APK и необходимые runtime-свидетельства; собственный полный source изучать обычными средствами |
| RLM Tools | Детерминированный анализ больших каталогов; без внутренних LLM-вызовов, модель которых нельзя ограничить указанными параметрами |
| OpenSpec / RTK / Caveman | Проверяемые требования и задачи; компактный вывод команд; краткие статусы без потери фактов |
| CodeGraph | Только если уже существует индекс; сейчас пропустить, новый индекс не создавать |
| Недостающий скилл | Сначала проверить установленные; просить конкретную ссылку только при установленном пробеле, объясняя задачу и причину; независимую работу продолжать |

Файл плана не переключает модель и reasoning в интерфейсе Codex. Эти ограничения проверяются при запуске основного агента и каждой делегации. Экономия вывода не сокращает анализ и обязательные проверки.

### Карта функциональности

Создать `research/FEATURE_COVERAGE.json` рядом с существующим EFFECTS_CATALOG.json, не теряя сырые исследования. Строка содержит: ID; приложение/package/version/SHA и происхождение; путь UI; тип функции; FREE/PRO/device-gated/unknown; входы; параметры с типом, единицами, диапазоном, default и зависимостями; поведение/seed/масштаб; доказательства; реализацию sf7b; проверки; отличия и неизвестное.

Охват: открытие/создание, источник/генераторы, цвет, весь каталог эффектов, наборы/рандомизация, слои/дерево/ветви/source2/blend/mask, текст/TTF/кисть, геометрия, Undo/Redo, галерея/копии/сохранение/перенос/восстановление, экспорт/share, темы/языки/настройки, обнаруженные анимация/видео. Вспомогательные классы, aliases и presets классифицировать отдельно. Одинаковые названия не доказывают одинаковую функцию.

Статусы вести по независимым осям: исследовано; реализовано; core/Android/A51 проверены; сравнение оригинала выполнено. До закрытия registry, UI-маршрутов, наследуемых схем и неизвестных регистраций проценты полноты не публиковать. Позже показывать отдельно покрытие всего известного каталога и runtime-доступной части; PRO и неизвестное не исчезают из знаменателя молча.

### Протокол REA

1. Переиспользовать сохранённые Evidence при совпадении APK SHA, версии инструмента и условий. Проверить точные APK из STATE, package/versionCode, ABI, сертификат и состав base/splits; не делать выводы из имени файла.
2. Следовать текущим схемам подключённых инструментов: `inspect_android_package`, поиск классов, точечные class/method inspection и `trace_android_references`. Выбирать перегрузку по фактическому inventory. При JNI/GLSL идти от подтверждённого вызова к библиотеке/ресурсу. Этот маршрут соответствует [официальному Android guide REA](https://github.com/morluto/rea/blob/main/.agents/skills/reverse-engineer-anything/references/android-applications.md); статические связи сами по себе не доказывают исполнение.
3. Дозавершить One Lab ordered groups и главный Glitch registry `FragmentGlitch.initGlitchTypes`; прежний небольшой subset не считать полным. Восстановить базовые и унаследованные схемы, преобразования значений, режимы, лицензионные/device gates, состав наборов и фактический dispatch.
4. Для каждого механизма записать поведенческий контракт до реализации: что преобразуется, нейтральное состояние, границы, sampling, цвет/alpha, координаты, random/seed, preview/export. Собственные допущения маркировать явно.
5. Runtime: одинаковые собственные fixtures, свежие foreground/XML/screenshot перед вводом, один параметр за опыт, сохранённые настройки и пара «вход — экспорт». Полные Evidence и SHA хранить локально; в контекст возвращать нужную страницу/сводку.
6. PRO не покупать и не запрашивать повторно уже отсутствующий доступ. По доступной статике можно делать собственную реализацию, сохраняя статус непроверенного runtime. Наблюдения mod относить только к нему. Недоступность телефона не останавливает независимую работу.

Внутренний анализ APK разрешён прямым ответом владельца в этом чате. Оригинальный код/GLSL/иконки/текстуры в свой APK и архив исходников не переносятся. Старый режим чистой комнаты для этой задачи отменён; правила доказательности и защиты личных работ действуют.

### Архитектура и распределение

Сохранить Kotlin/Compose и отдельное core. Один версионированный документ питает дерево, слои, CPU/GPU, Undo, thumbnail и экспорт. Original assets остаются в проекте; preview использует ограниченное разрешение. GL ES применяется для подтверждённых путей с CPU fallback. Исправлять измеренные узкие места, сохраняя точность и legacy; полной переписи без доказанной причины не планировать.

Root отвечает за EditorModel/UI-интеграцию, телефон, сборки и общий checkpoint. Два рабочих направления: REA/каталог и core/render/storage. Владельцев файлов закреплять до правок; для независимой проверки переиспользовать агента после завершения его пакета. На хосте 8 GB одновременно только один тяжёлый Gradle или JADX; ввод на телефоне отправляет только root. Не менять сети/питание/драйверы телефона и не очищать приложения.

Для временных режимов переиспользовать граф с явным временем; особенности random/цикла воспроизвести по evidence. Кадры декодировать/рендерить ограниченными буферами. Конкретные форматы/кодеки и бюджет выбрать по выявленным функциям и реальным возможностям A51. Последовательность PNG полезна для диагностики, но не заменяет требуемый видеоэкспорт.

### Проверки корректности и сходства

Fixtures: цветовые полосы/серый градиент, grid, импульс/границы, собственное фото, прозрачный объект; PNG, baseline/progressive JPEG, WebP lossy/lossless/alpha, EXIF, RGB-профили/P3/16-bit. Исходного проблемного файла владельца сейчас нет; частный случай затемнения остаётся невоспроизведённым.

Для эффекта проверять нейтральное, min/default/max и несколько промежуточных значений, каждый режим, palette/дополнительные входы, края/alpha, масштаб, разные пропорции, цепочку и seed после переноса. Для неизвестного seed оригинала сравнивать установленные свойства и статистику, а не требовать одинаковые случайные пиксели. Допуск/метрику задавать до сравнения; не расширять их ради прохождения.

Сравнивать экспорт, размеры и alpha; screenshot служит свидетельством UI. Для детерминированного PNG считать pixel diff и premultiplied RGB/alpha; для профилей использовать доверенное преобразование; для lossy/video учитывать кодек отдельно. CPU/GPU-проверки sf7b подтверждают внутреннюю согласованность, не паритет оригиналу.

Документ: A→B→A, independent copy, более 15 проектов, 15 смешанных слоёв, masks/blend/ветви/TTF, Undo/Redo, process death, ошибка/отмена импорта, удалённые внешние ресурсы, clean-profile portable import, damaged/missing current и backup. Текущие fixtures 192×144 и preview 512 не заменяют полноразмерную проверку 15 слоёв на A51.

### Цели скорости на A51

| Сценарий | Цель из SPEC |
|---|---|
| Открытие с пригодным preview | ≤3 с |
| Прогретая простая коррекция | ≤1 с |
| Тяжёлый эффект после изменения | ≤3 с; отдельно обоснованные тяжёлые случаи ≤10 с |
| Кэшированное переключение проекта | ≤3 с |
| Полный PNG обычной работы | ориентир ≤15 с; сложные цепочки отдельно |
| Pan/zoom | устойчивые ≥30 FPS без блокировки UI |

Входы 1980×1080, 2000², 3000² и отдельный крупный stress case; цепочки 1/5/10 эффектов и 15 слоёв. Измерять пользовательский интервал import/slider/open/export отдельно от kernel; холодный/тёплый режим, минимум три повтора, медиану/разброс, память/PSS/пик и условия температуры/зарядки. Сравнение оригиналов — только при сопоставимых входах и настройках.

Multi Distort около 18,8 с в историческом CPU benchmark остаётся открытой задачей. Быстрый cache hit и GPU-only PNG candidate10 не доказывают достижение всех целей. Глобальные cache/texture budgets подбирать по реальной памяти; для нелокальных эффектов нужны глобальные координаты и достаточные соседние области.

## Risks / Trade-offs

- Неполный registry или унаследованные параметры дают ложную полноту: сверять код, UI, наборы и dispatch; сохранять незакрытые ветви.
- PRO/mod ограничивают доказуемый паритет: продолжать собственную реализацию, явно оставлять непроверенное и не обещать официальный результат.
- Cache, GPU rounding и миграции могут менять старые проекты: сохранять algorithmVersion, контрольные результаты и отдельный путь legacy.
- 15 слоёв на малом fixture не доказывают рабочую память: проверять полноразмерные документы, spill, отмену и очистку только собственных временных файлов.
- Эмулятор ранее не загрузился: повторять только при новой причине/изменении условий; A51 учитывать отдельно, не задерживая host/static работу.

## Migration Plan

1. До будущих изменений сохранить checkpoint source, проверенный APK, private backup проектов и подпись вне публичных архивов. Канонический STATE остаётся на Desktop; source/STATE — ссылка на него.
2. Завершить candidate11, записать новые hashes/сертификат и установить через update `install -r`, сохранив данные. Новые тесты создают собственные UUID и восстанавливают прежние prefs/selection.
3. Новые алгоритмы/поля вводить явно версионированно; старые документы не менять молча. Неизвестные несовместимые версии отвергать с объяснением. После миграции сохранять last-good; не делать downgrade поверх нового формата.
4. При регрессии остановить поставку, сохранить диагностику и восстановить проверенную комбинацию APK/формата из отдельной копии. Не удалять оригинальные работы и не выполнять `clear`/`uninstall` как способ отката.
5. Финал: APK/исходники, BUILD_AND_INSTALL_RU, ROOT_CAUSES, REA_FINDINGS, FEATURE_COVERAGE/EFFECT_PARITY, DESIGN/UI_PARITY, TEST_REPORT/PERFORMANCE, PROJECT_FORMAT/LICENSE и актуальный STATE. В `<repository>\docs\analysis` — ONE_LAB_INTERNALS.md, GLITCH_LAB_INTERNALS.md, SF7B_LAB_GAPS.md. Полные анализы — в файлах.

Точные команды для первого будущего этапа из папки Android-исходников:

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17'
.\gradlew.bat '-Psf7bBuildRoot=<local-private-path>' --no-daemon --max-workers=1 --no-parallel '-Dorg.gradle.jvmargs=-Xmx1024m -Dfile.encoding=UTF-8 -XX:ActiveProcessorCount=2' '-Pkotlin.compiler.execution.strategy=in-process' :core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

Новый APK проверять после успешного assemble; оставшийся app-debug.apk не считать candidate11 автоматически. Сведения о готовности и точные дальнейшие команды заносить в STATE/notes после значимого результата и checkpoint до переполнения контекста. Полная готовность требует фактических проверок, не завершённого чек-листа на словах.
